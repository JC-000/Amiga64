- It reads a MOD staged in guest chip RAM (the REU).

On VICE it is silent, but every Paula register effect and every replay tick is checked against host references.

## Memory budget (read before writing code)
- **MAIN is full:** CODE ends below $8D00, LOWCODE below $0900, BSS ends near $9F47.
  - New MAIN bytes need a supervisor ruling.
  - Only hook lines (a `jmp`/`jsr` into a module) should land in MAIN; the code lives elsewhere.
- **Candidate homes:**
  - BCODE $A000-$B5FF (banked, BASIC ROM out; ~3.6 KB free as of Wave 11; measure it);
  - a machine-mode module in `buf_case` (mboot $C000-$C1FF, td $C200-$C5FF, spr $C600-$C8FF, inp $C980-$C9FE are taken);
  - under-I/O RAM claimed through rescheck.
- **The rule:** each package's M0 note proposes its addresses, and the supervisor rules before code lands.
- Guest chip RAM, the program and the MOD all live in the REU. The sampler reads the REU directly (START = `$1000000` + REU offset), so a Paula channel can play straight from guest chip RAM with no copying.

## Interfaces between the packages (binding)

**I-1 `mod_view`: the player state the UI shows.** It lives in guest chip RAM at the fixed address **`$000400`**, big-endian, 72 bytes. W15-M writes it; W15-U only reads it.

| Off | Size | Field |
|---|---|---|
| 0 | 4 | magic `'MVW1'` |
| 4 | 4 | tick counter (u32, +1 per replay tick) |
| 8 | 20 | song name (MOD header, NUL-padded) |
| 28 | 1 | song length (positions) |
| 29 | 1 | position |
| 30 | 1 | pattern |
| 31 | 1 | row (0-63) |
| 32 | 1 | speed (ticks/row) |
| 33 | 1 | BPM |
| 34 | 1 | flags: bit 0 playing, bit 1 has looped, bit 2 the CIA tempo is in use (not VBL) |
| 35 | 1 | pad (0) |
| 36 | 4×8 | channel 0-3: period (u16), instrument (u8, 0 = none), volume (u8, 0-64), note (u8, 0-35 = C-1..B-3, $FF = none), effect (u8), param (u8), vu (u8, 0-64; set on a note trigger, decays per frame) |
| 68 | 4 | the elapsed play time in 1/50 s (u32) |

The UI must tolerate any value (clamp what it shows). The replay must keep the struct consistent per tick: it writes a tick's fields together, outside the UI's frame call.

**I-2 The program's split.** One machine-mode Amiga program, built from `fixtures/mod/`.
- **W15-M owns** main(), the interrupts, the CIA timers, Paula, and the replay.
- **W15-U owns** the display: the copper list, the bitplanes, the palette, and all drawing. It provides two entry points with vbcc's m68k C ABI:
  - `void ui_init(void)`, called once before the music starts;
  - `void ui_frame(const struct mod_view *v)`, called by main once per vertical blank, outside the interrupt handler.
- W15-M never touches a display register. W15-U never touches Paula, the CIAs or the interrupt enables.
- Before the two meet, each tests alone:
  - W15-U runs its screen from a host-written `mod_view`.
  - W15-M runs with a stub `ui_frame` that does nothing.

**I-3 Paula.** The program drives Paula exactly as on an Amiga:
- AUDxLCH/L, AUDxLEN, AUDxPER and AUDxVOL ($0A0-$0DA);
- DMACON AUD0-3EN and DMAEN;
- INTENA/INTREQ AUD0-3 (level 4).

Whatever W15-P supports is written down in CONTRACTS "Audio (Paula)". W15-M uses only that, and anything else it needs goes to the supervisor as a request.

## W15-P — Paula on the U64 sampler

Facts to use: docs/HARDWARE.md "U64 sampler (Ultimate Audio)" (W10-H):
- The register map. Voices 0-6 are reachable.
- Sample time = (rate + 1) × 160 ns + 118 ns.
- A volume of 64 wraps to 0, so send 63.
- A loop raises no IRQ.
- A stopped voice holds its last sample as DC.
- The REPEAT B == LENGTH hazard.

docs/ARCHITECTURE.md (the audio line) has the decision: one sampler voice per Paula channel, played from the REU.

- **P0 (M0 note, first):**
  - The audio-register path today: chip.s shadows $0A0-$0DF and then goes to `cop_w0`.
  - Your hook points.
  - Where the code lives (addresses).
  - How AUDx interrupts are timed: from the guest's time base, via mach event slots? Which slot?
  - **The time-base question:** guest time runs at E = φ2 >> s, with frame = 14188 E. Paula's pitch on the sampler is real-time, but a replay's tempo follows guest VBL/CIA time. Measure the real-time ratio of guest time on the U64E at 48 MHz for the s values in use, and propose how a MOD can play at the right tempo. For example: an `s` or E-rate setting for this profile, or real-time-paced VBL for the player. This question decides the wave, so report it early.
- **P1:** the register model (host/paula_ref.py) and the runtime on VICE.
  - The channel state machine: LC/LEN latched at DMA start; the block-end interrupt; the reload from the latches; PER and VOL taking effect at once; DMACON on/off.
  - A host-visible state block for tests.
  - Red first.
- **P2:** the U64E backend. Each channel maps to a sampler voice:
  - START from the REU address of chip RAM;
  - RATE from PER;
  - VOL capped at 63;
  - loop = the REPEAT mode, with REPEAT A/B from the reloaded block;
  - the block-end AUDx interrupt timed from the 6510 side;
  - zero-play on DMA off (the DC hold).

  Hardware legs capture the UDP audio stream and check pitch per PER and level per VOL, and that the program's interrupts arrive at the predicted guest times.
- **P3:** the cost report: cycles per AUDx write, per block-end event, and idle.

## W15-U — UI that stays readable after c2v

Facts (docs/C2V.md, CONTRACTS "Display refresh"):
- 2-plane lores 320 px becomes VIC multicolour at 160 px, taking the LEFT pixel of each pair, so single-pixel columns vanish.
- Colours go through the OCS→VIC LUT.
- Each 4×8 MC cell has the background colour plus three colours.
- Hires becomes a 1-bit silhouette.
- The fit view crops 256 lines to 200, top-anchored (W14-D), and the 1:1 view pans.
- The user's verdict on the AROS insert-disk text (Wave 12): "visible, but the text is too compressed to read".

- **U0 (M0 note, first):** `docs/UI_READABLE.md`, the rules. For example:
  - lores 2-plane only;
  - glyphs drawn on the 160-px grid (2-px strokes), at least 8 px tall;
  - colours chosen from the LUT so they stay distinct;
  - per-cell colour limits respected;
  - everything important within the top 200 lines;
  - how to check each rule.

  Include a preview of a font sample rendered through `host/c2v_ref.py` as PNGs (send the paths). The supervisor shows these to the user.
- **U1:** the UI kit in 68k: text, numbers, bars (VU), boxes, highlight, written for the vbcc ABI. Also `host/ui_preview.py`, which renders a guest screen dump (or a host model of the same drawing) through c2v_ref into a PNG at VIC resolution.
  - The readability checks, with teeth:
    - every glyph of the font is distinct after conversion;
    - text/background contrast holds after the LUT;
    - no cell exceeds its colours.
  - Mutants: a 1-px font, a too-close colour pair.
- **U2:** the player screen from `mod_view`. Show:
  - the song name;
  - position/pattern/row;
  - speed/BPM;
  - the time;
  - four channel strips (instrument, note, volume, effect) with VU bars;
  - optionally the current pattern rows around the playing row.

  It updates within the frame budget: measure the cycles per `ui_frame` on VICE, and make the drawing incremental.

  Run it on VICE with a host-written `mod_view` sequence. Previews go to the supervisor for the user.

## Addendum: supervisor rulings (2026-10-12)
- **Time base (W15-P R3 = W15-M's proposal):**
  - The player profile runs at **s = 0** on the U64E.
  - The replay is paced in real time by CIA-B TA: tick_e = (1022727/50) >> s = 20455 at s = 0. VBL-speed songs count as 125 BPM.
  - VERTB (72.08 Hz) paces only ui_frame and the mod_view publish.
  - The replay runs from the level-6 interrupt with tick catch-up.
  - Paula interrupts use R = E per colour clock as a profile factor (0.28834 at s = 0 on the U64E).
  - Known deviation: E = 1.0227 MHz in this profile.
  - Backlog: an exact real-time E in mach.s (option a).
  - To verify: the s = 0 guest-starvation backlog item.
- **W15-P memory:**
  - The `aud` module at $CA00-$CDFF (code to $CCFF, state block $CD00). Player profile only, mutually exclusive with aros_resume (rescheck claim plus a module-ID guard).
  - The chip.s router ≤ 32 B CODE plus a 2 B BSS `aud_vec`.
  - mach slot 6.
  - The sampler's own IRQ is never enabled.
  - The sampler backend is enabled only by a host flag inside the U64E hold.
- **W15-M:**
  - No new C64 bytes. The mboot load path.
  - The guest map: image $010000-$03FFFF, params $000480, status $0004C0, MOD $080000-$1FFFFF.
  - `fixtures/mod/mod_view.h` is W15-M's; W15-U includes it read-only.
  - Paula LC/LEN follow HRM latch semantics (latched at DMA start and at each block end).
- **W15-U:**
  - Guest chip RAM $040000-$07FFFF.
  - ui_frame at 72 Hz, averaging ≤ ~400 68k instructions per call (worst ≤ ~1500); incremental drawing.
  - Open: CPU-drawn pixels do not mark the display dirty (CONTRACTS +105). W15-U proposes a mechanism; the supervisor rules.
- **I-1 semantics:** vu decays per replay tick; elapsed += 125/BPM per tick (16.16, in 1/50 s).
