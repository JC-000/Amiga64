# M0 — end-to-end loader demo

M0 exit criterion (ARCHITECTURE.md): an Amiga Hunk executable is parsed on
the host, laid out into guest (REU) memory, executed by the interpreter,
and its results verified from guest memory.

## Run it

```sh
make runtime                      # build/runner.prg + runner.lbl
python3 -m tests.run_program --prg build/runner.prg
```

Exit code 0 means every check passed. Options:

- `--fixture minimal|reloc|all` — which canned fixture(s) to run (default
  `all`). `minimal` = `MOVEQ #1,D0; HALT`; `reloc` = `MOVE.L (abs.L),D0;
  HALT` with the address field RELOC32-patched to a data hunk, proving
  relocation + image layout + interpretation in one register value
  (`D0=55667788`).
- `--hunk FILE` — stage and run an arbitrary Hunk executable instead
  (final state is printed; no canned expectations).
- `--budget N` — max guest instructions (default 10000, `0` = unlimited).
- `--labels / --timeout / --backend` — as in `tests.run_vectors`.

Host-only pipeline tests (no VICE): `pytest -q host/tests/test_m0_pipeline.py`.

## Pipeline

1. `host/fixturegen.py` builds a Hunk executable (hand-encoded 68k words).
2. `host/hunk.py` parses it; `host/image.py` lays out segments from
   `$010000` (4-byte aligned, BSS zero-filled), applies RELOC32, and
   produces sparse chunks + a manifest (`entry`, `stack_top = $00F000`).
3. Chunks are split into buf_case-sized records (≤ 2 KB, same
   `{u32 LE offset, u32 LE len, data}` framing as `image.bin`) and staged
   into REU via the C64-side `test_load_chunk` entry
   (`tests/runner/run_program.s`), which feeds every byte through the
   interpreter's `mem_write8`. This path was chosen over a VICE
   `-reuimage` preload because it is backend-agnostic (same mechanism
   will work on Ultimate 64 hardware), exercises the contract memory API,
   and needs no VICE-specific file handling; fixture-sized images make
   its per-byte cost irrelevant.
4. For the canned fixtures the driver reads every staged byte back
   through `mem_read8` (host writes `m_addr` at `$58`, calls the label,
   reads `m_val` at `$5C`) before running.
5. `test_run_program` does `emu_reset`, sets `PC = entry`,
   `A7 = stack_top` (all other registers and SR are zero), then loops
   `emu_step` counting executed instructions until `st_halt != 0` or the
   budget is exhausted (timeout flag). The halting instruction is
   counted, so `MOVEQ; HALT` reports 2 instructions.

## test_run_program result block (`buf_result`, $C800)

| Offset | Size | Contents |
|---|---|---|
| +$00 | 1 | done flag ($00 busy, $FF complete) |
| +$01 | 1 | `st_halt` copy |
| +$02 | 1 | `st_reason` copy (`HALT_OK` = $00 for pseudo-op $AFFF) |
| +$03 | 1 | timeout flag ($01 = budget exhausted before halt) |
| +$04 | 4 | executed-instruction count (u32 LE) |
| +$10 | 70 | final D0–D7/A0–A7, PC, SR — same layout as `test_run_case` |

`test_run_case` (M1 vector runner) is unchanged; the loader entries live in
`tests/runner/run_program.s`, picked up by the Makefile wildcard.
